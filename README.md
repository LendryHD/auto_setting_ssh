# Synet SSH Hardening

Русскоязычный скрипт защиты SSH для Ubuntu Server 22.04, 24.04 и 26.04.

**SSH остаётся на стандартном порту 22**. Скрипт не выбирает случайный порт и не изменяет `ssh.socket`. Если SSH на сервере не слушает порт 22, скрипт прекращает настройку, а не пытается перенастроить сеть.

> Важно: перед запуском сохраните доступ к консоли VPS у провайдера и убедитесь, что у вас есть приватный SSH-ключ, соответствующий публичному, который собираетесь указать. Скрипт ещё не тестировался в полноценном сценарии на реальном VPS.

## Запуск одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/LendryHD/auto_setting_ssh/main/synet-ssh-hardening.sh -o /tmp/synet-ssh-hardening.sh && sudo bash /tmp/synet-ssh-hardening.sh
```

Скрипт запросит имя пользователя, пароль пользователя для `sudo` и **одну строку публичного SSH-ключа** (`ssh-ed25519 AAAA...`). Приватный ключ никогда не вставляйте в скрипт.

Настраивает пользователя и `sudo`, добавляет ключ в `~/.ssh/authorized_keys`, отключает SSH-вход под `root` и по паролю. Порт остаётся 22. Существующие правила UFW и внешний файрвол не меняются.

## Подтверждение входа

**Не закрывайте текущую SSH-сессию.** Откройте второй терминал и подключитесь к порту 22 под настроенным пользователем с приватным ключом:

```bash
ssh -p 22 -i /путь/к/приватному_ключу пользователь@IP_СЕРВЕРА
```

В **новой** SSH-сессии выполните точно:

```bash
sudo env SYNET_CONNECTED_PORT="${SSH_CONNECTION##* }" /usr/local/sbin/synet-ssh-guard --confirm
```

Если подтверждение не поступит за 15 минут, systemd-таймер попробует вернуть предыдущую конфигурацию SSH. Он не отменяет создание пользователя, изменение пароля и добавление ключа. Если таймер или служба SSH работают некорректно, используйте консоль провайдера.

## Важные особенности

- Скрипт **не переносит** SSH обратно на порт 22, если сервер раньше был перенастроен на иной порт: в этом случае он откажется запускаться.
- После работы скрипта прежние автоматизации с SSH-подключением под `root` (например, eGames) потребуют перенастройки.
- Изменение конфигурации SSH — рискованная операция: сначала испытайте скрипт на тестовом VPS.
- Для производственного использования лучше фиксировать проверенную версию скрипта по конкретному Git commit SHA, а не полагаться на изменяемую ветку `main`.
